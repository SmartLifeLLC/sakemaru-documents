# S9: テスト計画 v1

- ステータス: finalized
- 目的: 同期の安全性・整合性を事前保証

## テスト区分

1. 単体
- キー生成
- 差分判定
- enum変換
- 正規化関数

2. 結合
- 抽出 -> 変換 -> 書込（dry-run/apply）
- checkpoint 再開
- retryable/non-retryable 分岐

3. E2E
- Admin UI から手動実行
- エラー確認と再実行

4. データ整合
- source件数とtarget件数突合
- client越境ゼロ検証

## 合格基準

- 重大不整合（越境/二重反映/漏れ）0件
- 2回連続実行で2回目差分が想定どおり収束
- 想定処理時間内（client規模別SLO）

## 検証

- テストケース網羅表で未実施項目なし。

## ロールバック

- 失敗カテゴリ単位で機能フラグOFFし、dry-runに戻す。

## リスク

- 低: テストデータ偏り。
- 中: 実データ特性差の見落とし。
