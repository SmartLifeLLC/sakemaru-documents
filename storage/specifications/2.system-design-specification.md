## 1. システム全体構成

### 1.1 酒丸エコシステム内の位置付け

酒丸帳場は、酒丸基幹システム群の一部として動作する電子帳簿管理アプリケーションである。

| システム名 | プロジェクト | ドメイン | 役割 |
|-----------|-------------|---------|------|
| 酒丸WMS | sakemaru-wms | wms.sakemaru.test | 倉庫管理 |
| 酒丸乃蓮 | sakemaru-trade | trade.sakemaru.test | 取引管理 |
| **酒丸帳場** | **sakemaru-documents** | **documents.sakemaru.test** | **電子帳簿管理** |

- すべてのシステムは `*.sakemaru.test` ドメイン配下で動作する
- 管理者ユーザー（`users` テーブル）はシステム間でセッションを共有する（SSO）
- 共通データベース（`sakemaru` 接続）を通じてマスタデータを参照する

### 1.2 パネル構成

| パネル | パス | 対象ユーザー | 認証テーブル | Auth Guard |
|--------|------|-------------|-------------|------------|
| 管理者パネル | `/admin` | 社内管理者 | `users`（sakemaru DB） | `web` |
| 取引先パネル | `/partner` | 取引先（顧客） | `partners`（sakemaru DB） | `partner` |

### 1.3 データベース接続構成

```
┌─────────────────────────────────────────────────┐
│ sakemaru DB (共有)                                │
│  ├── users          ← 全アプリ共有（管理者認証）      │
│  ├── sessions       ← 全アプリ共有（セッション）      │
│  ├── partners       ← 全アプリ共有（取引先マスタ/認証）│
│  ├── documents      ← 帳場専用                      │
│  └── audit_logs     ← 帳場専用                      │
│                                                     │
│ documents DB (専用)                                  │
│  ├── clients        ← テナント識別                   │
│  └── (その他帳場専用テーブル)                         │
└─────────────────────────────────────────────────┘
```

## 3. 認証・認可アーキテクチャ

### 3.1 Auth Guard 構成

**config/auth.php:**

```php
'guards' => [
    'web' => [
        'driver' => 'session',
        'provider' => 'users',
    ],
    'partner' => [
        'driver' => 'session',
        'provider' => 'partners',
    ],
],

'providers' => [
    'users' => [
        'driver' => 'eloquent',
        'model' => env('AUTH_MODEL', App\Models\Sakemaru\User::class),
    ],
    'partners' => [
        'driver' => 'eloquent',
        'model' => App\Models\Partner::class,
    ],
],
```

**重要:** 管理者の `AUTH_MODEL` は `App\Models\Sakemaru\User::class` を使用する。これはWMS・Trade側とのセッション互換性を保つためのクラスパス統一。

### 3.2 User モデル（管理者認証）

管理者認証は酒丸エコシステム全体で共有される `users` テーブルを使用する。

**app/Models/User.php:**

```php
namespace App\Models;

use Illuminate\Foundation\Auth\User as Authenticatable;

class User extends Authenticatable
{
    protected $connection = 'sakemaru';
    protected $table = 'users';

    protected $fillable = ['name', 'email', 'password'];

    protected $hidden = ['password', 'remember_token'];

    protected function casts(): array
    {
        return [
            'email_verified_at' => 'datetime',
            'password' => 'hashed',
        ];
    }
}
```

**app/Models/Sakemaru/User.php:** (セッション互換エイリアス)

```php
namespace App\Models\Sakemaru;

use App\Models\User as BaseUser;

/**
 * WMS/Trade セッション互換性のためのエイリアス。
 * WMSはセッションに 'App\Models\Sakemaru\User' のクラス名で保存するため、
 * このクラスが存在しないとセッションデシリアライズが失敗する。
 */
class User extends BaseUser
{
    // BaseUser の機能をすべて継承
}
```

### 3.3 Partner モデル（取引先認証）

取引先は `partners` テーブルで認証する。既存の `partners` テーブル（sakemaru DB）に認証用カラムを追加する。

**app/Models/Partner.php:**

```php
namespace App\Models;

use Filament\Models\Contracts\FilamentUser;
use Filament\Panel;
use Illuminate\Foundation\Auth\User as Authenticatable;

class Partner extends Authenticatable implements FilamentUser
{
    protected $connection = 'sakemaru';
    protected $table = 'partners';

    protected $fillable = [
        'code',
        'name',
        'email',
        'password',
        'is_supplier',
        'is_active',
    ];

    protected $hidden = ['password', 'remember_token'];

    protected function casts(): array
    {
        return [
            'password' => 'hashed',
            'is_supplier' => 'boolean',
            'is_active' => 'boolean',
        ];
    }

    public function canAccessPanel(Panel $panel): bool
    {
        return $this->is_active;
    }
}
```

**partners テーブルへの追加カラム（マイグレーション）:**

```php
Schema::connection('sakemaru')->table('partners', function (Blueprint $table) {
    $table->string('email')->nullable()->unique()->after('name');
    $table->string('password')->nullable()->after('email');
    $table->boolean('is_active')->default(true)->after('is_supplier');
    $table->rememberToken()->after('is_active');
});
```

**既存データ補足:** `email` の unique については酒丸側で対応済み。

### 3.4 LoginResponse（パネル別リダイレクト）

**app/Http/Responses/LoginResponse.php:**

```php
namespace App\Http\Responses;

use Filament\Facades\Filament;
use Filament\Http\Responses\Auth\Contracts\LoginResponse as LoginResponseContract;

class LoginResponse implements LoginResponseContract
{
    public function toResponse($request)
    {
        $panelId = Filament::getCurrentPanel()->getId();

        return match ($panelId) {
            'admin' => redirect()->to('/admin'),
            'partner' => redirect()->to('/partner'),
            default => redirect()->to('/' . $panelId),
        };
    }
}
```

**AppServiceProvider での登録:**

```php
use Filament\Http\Responses\Auth\Contracts\LoginResponse as LoginResponseContract;
use App\Http\Responses\LoginResponse;

public function register(): void
{
    $this->app->singleton(LoginResponseContract::class, LoginResponse::class);
}
```

## 4. クロスアプリケーション セッション共有

### 4.1 セッション共有の前提条件

| 要件 | 設定値 |
|------|--------|
| セッションドライバ | `database` |
| セッションDB接続 | `sakemaru`（共有DB） |
| セッションテーブル | `sessions`（共有DB内） |
| セッションドメイン | `.sakemaru.test`（先頭ドット） |

| APP_KEY | 全アプリで同一 |

**補足:** `sessions` テーブルは `sakemaru` 接続側に作成する（migration 実行時は `sakemaru` を対象にする）。

### 4.2 .env 設定

```env
APP_NAME="酒丸-帳場"
APP_URL=https://documents.sakemaru.test
APP_KEY=（WMS/Trade と同一のキーを使用）

# Database
DB_CONNECTION=mysql
DB_DATABASE=sakemaru_document_local
DB_HOST_SAKEMARU=127.0.0.1
DB_DATABASE_SAKEMARU=sakemaru_hana_prod

# Session (クロスアプリ共有)
SESSION_DRIVER=database
SESSION_DOMAIN=.sakemaru.test
SESSION_COOKIE=sakemaru_session
SESSION_LIFETIME=3600  # 分単位（60時間）
SESSION_ENCRYPT=false
SESSION_SECURE_COOKIE=true
SESSION_PATH=/
SESSION_CONNECTION=sakemaru
```

### 4.3 config/session.php

```php
'connection' => env('SESSION_CONNECTION', 'sakemaru'),
```

### 4.4 AuthenticateSession ミドルウェアの無効化

管理者パネルでは `AuthenticateSession` ミドルウェアを無効化する。これはクロスアプリケーション間でパスワードハッシュ検証が失敗し、セッションがクリアされる問題を防ぐため。

```php
// AdminPanelProvider.php
->middleware([
    EncryptCookies::class,
    AddQueuedCookiesToResponse::class,
    StartSession::class,
    // AuthenticateSession::class, // Disabled for cross-app session sharing
    ShareErrorsFromSession::class,
    VerifyCsrfToken::class,
    SubstituteBindings::class,
    DisableBladeIconComponents::class,
    DispatchServingFilamentEvent::class,
])
```

Partner パネルは独立した認証のため、`AuthenticateSession` を有効にしてよい。

### 4.5 Sanctum 設定

Trade側の `.env` に帳場ドメインが既に含まれていることを確認:

```env
SANCTUM_STATEFUL_DOMAINS=sakemaru.test,...,documents.sakemaru.test,...
```

帳場側にも同様に設定:

```env
SANCTUM_STATEFUL_DOMAINS=sakemaru.test,wms.sakemaru.test,trade.sakemaru.test,documents.sakemaru.test
```

### 4.6 動作確認チェックリスト

- [ ] 全アプリで同じ `APP_KEY` を設定
- [ ] 全アプリで同じ `SESSION_DOMAIN=.sakemaru.test` を設定
- [ ] 全アプリで同じ `SESSION_COOKIE=sakemaru_session` を設定
- [ ] 全アプリで同じ `SESSION_CONNECTION=sakemaru` を設定
- [ ] `App\Models\Sakemaru\User` エイリアスクラスを作成

- [ ] AdminPanelProvider で `AuthenticateSession` を無効化
- [ ] WMS/Trade にアクセス後、帳場の `/admin` にもログイン状態で入れること
- [ ] 帳場でログイン後、Trade の `/admin` にもログイン状態で入れること

## 6. デザイン・レイアウト方針

酒丸乃蓮（Trade）および酒丸WMSで確立されたデザインパターンを踏襲する。

### 6.1 デザイン原則

| 原則 | 説明 |
|------|------|
| コンパクト・高密度テーブル | テーブル行の高さを最小限に、パディング削減、データ中心のUI |
| スティッキー要素の活用 | テーブルヘッダー固定、アクションカラム右端固定 |
| 日本語UX | すべてのラベル・メッセージを日本語化、業務用語準拠 |
| ダークモード対応 | 全コンポーネントに `dark:` スタイルを定義 |
| モーダル中心のワークフロー | 詳細・編集はモーダルで完結、ページ遷移を最小限に |
| アイコンの一貫性 | UI全般: Heroicons (`heroicon-o-*`)、メガメニュー: Font Awesome 6 |

### 6.2 メガメニュー（管理者パネル）

管理者パネルはFilament標準のtopbarを置き換え、メガメニューを実装する。

**構成ファイル:**

```
app/
├── Livewire/MegaMenu.php                    # Livewireコンポーネント
├── Enums/EMenuCategory.php                  # メニューカテゴリEnum
resources/views/
├── livewire/mega-menu.blade.php             # メガメニューテンプレート
└── vendor/filament-panels/components/layout/
    └── index.blade.php                      # レイアウト（メガメニュー呼び出し）
```

**スタイリング仕様:**

| 要素 | スタイル |
|------|---------|
| ヘッダー背景 | `bg-slate-800` |
| ヘッダー高さ | `h-10`（40px） |
| タブ通常 | `text-slate-200 hover:text-white hover:bg-slate-700` |
| タブアクティブ | `text-white bg-slate-700` |
| ドロップダウン背景 | `bg-white rounded-lg shadow-lg border border-slate-200` |
| メニューアイテムホバー | `group-hover:bg-indigo-600` |
| アクティブアイテム | `text-indigo-600 bg-indigo-50` |

**セットアップ手順:**

1. `php artisan make:livewire MegaMenu`
2. 上記ファイルを配置
3. `php artisan vendor:publish --tag=filament-panels-views`
4. レイアウトファイルで標準topbarをメガメニューに置換
5. AdminPanelProvider で `->topNavigation()` 有効化
6. `npm run build`

### 8.4 電帳法対応フィルタパターン

```php
use Filament\Tables\Filters\Filter;
use Filament\Forms\Components\DatePicker;
use Filament\Forms\Components\TextInput;

// 日付範囲検索
Filter::make('transaction_date')
    ->form([
        DatePicker::make('from')->label('開始日'),
        DatePicker::make('to')->label('終了日'),
    ])
    ->query(function (Builder $query, array $data): Builder {
        return $query
            ->when($data['from'], fn ($q, $date) => $q->whereDate('transaction_date', '>=', $date))
            ->when($data['to'], fn ($q, $date) => $q->whereDate('transaction_date', '<=', $date));
    }),

// 金額範囲検索
Filter::make('amount')
    ->form([
        TextInput::make('min')->label('最小金額')->numeric(),
        TextInput::make('max')->label('最大金額')->numeric(),
    ])
    ->query(function (Builder $query, array $data): Builder {
        return $query
            ->when($data['min'], fn ($q, $min) => $q->where('amount', '>=', $min))
            ->when($data['max'], fn ($q, $max) => $q->where('amount', '<=', $max));
    }),

// 取引先名 部分一致
Filter::make('partner_name')
    ->form([
        TextInput::make('name')->label('取引先名'),
    ])
    ->query(function (Builder $query, array $data): Builder {
        return $query->when($data['name'], fn ($q, $name) => $q->where('partner_name', 'like', "%{$name}%"));
    }),
```
